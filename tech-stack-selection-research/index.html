TL;DR 一页速览

没有"最好的语言"，只有"对这个人群 + 这个需求 + 这个项目最合适的语言"。

01

当成正式决策来做

定维度 → 加权打分（5–8 个判据）→ 跑原型验证 → 用 ADR 把"为什么选它、放弃了什么"写进代码仓库。

02

默认"选无聊技术"

每个团队的"创新代币"约只有 3 个，花在真正的业务创新上。警惕"简历驱动开发"反模式。

03

平台约束常直接锁死

目标在浏览器、要零安装 → 几乎只能 JS/TS（WebAssembly 作补充）。

04

团队 + 招聘是硬约束

Python/JS/Java 人才池最深；Rust 连年"最受推崇"（约 72–83%）但使用率仅约 12.6%，要算上学习曲线与招聘成本。

05

人机分工的黄金线

技术选型与架构权衡是人类的活；AI 适合起草规格、拆任务、扩展候选方案、做一致性检查。

06

别被提效数字带偏

DORA 2025 定性最准："AI 是放大器，不会修复团队，只会放大已有的好坏。"

METHOD 通用选型方法论

第一步不是比语言，而是拆需求；然后用可量化的框架把决策做出来、记下来。

六个核心评估维度

  • 项目目标 / 需求匹配度 — 区分功能性需求与非功能性需求
  • 团队现有技能与上手成本 — 学习曲线
  • 性能与可扩展性 — 以未来 3–5 年业务量为基准，而非当前量
  • 可维护性与长期生命力 — 社区活跃度、问题解决速度、业界案例
  • 安全与合规
  • 总体拥有成本 TCO — 开发 + 维护 + 招聘成本

加权评分矩阵 高

判据设权重 → 候选方案打分 → 算 Σ(权重×分数)。判据控制在 5–8 个（超过 10 个会稀释信号）。日常最常用。

AHP 层次分析法 高

两两成对比较把主观因素定量化，输出优先级。判据多、利益相关方多、要正式论证时用。

ADR 架构决策记录 高

用轻量 Markdown 记 Status/Context/Decision/Consequences/Alternatives/Trade-offs，与代码同仓库。

反模式：什么时候"不要"选某语言

  • 选无聊技术（Dan McKinley, 2015）：别用新潮但未经验证的技术替换成熟件——新技术"未知的未知"更多。
  • 简历驱动开发：为简历引入时髦栈，作者走后留下无法维护的系统。
  • 招聘单点故障：Go 岗位约为 Rust 的 3–4 倍；没有"Rust 形状的问题"别默认重写。

SCENE 场景落地 · indie / 游戏×AI

把通用框架落到独立开发者最常用的几条栈上，配真实案例。

🕹️ 浏览器 2D 游戏

Phaser 3/4 + TypeScript + Vite。官方 template-vite-ts 模板，HMR 热重载。坑：内置匿名统计 log.js，用 dev-nolog 关。

⚔️ 真实案例

《吸血鬼幸存者》先用 Phaser 做，1.6 版后迁移到 Unity，桌面版用 Electron 打包。"Phaser 原型 → Unity/Electron"是被走通的演进路径。

🎬 视频自动化

Remotion（用 React 以代码生成视频）。坑：非纯 MIT 免费，部分商用需买公司授权——计划阶段就要算进 TCO。

☁️ 部署

Cloudflare Pages/Workers。免费档约 10 万请求/天，可组合 D1/R2/KV，对 indie 全栈友好。

🐍 自动化胶水

Python 串联抓取→清洗→LLM 生成→发布。高性能 CLI 才考虑 Rust（否则 Go/Node 更快出活）。

💡 indie 最贵的一课

尽快发布优先于完美技术栈——很多独立开发者死于"完美主义无法发布"。

★ BOSS BATTLE · RCT 对决 ★
METR 2025
−19%

资深开源开发者，在自己极熟的成熟大仓做真实任务，反而慢了 19%。事前还预期提速 24%。

VS
GitHub Copilot RCT
+55.8%

95 名程序员做孤立绿地小任务（写个 HTTP server），含较多新手，完成快 55.8%。

判定：场景决定结论，两者不可直接比较。 DORA 2025 的定性最实用——「AI 是放大器，不会修复团队，只会放大已有的好坏」。对独立开发者：AI 在绿地原型 / 陌生探索 / 起草规格上收益最大（正是 indie 主场）；在你已极熟的代码里精改时，把 AI 用在"评审/查错/写测试"比"代写"更划算。

规格驱动开发（SDD）把分工固化进流程

  • GitHub Spec Kit 五阶段：constitution → specify（只写 what/why）→ plan（这一步才由人类填技术栈） → tasks → implement。
  • Amazon Kiro 产出三件套 requirements/design/tasks，用 EARS 语法写验收标准。
  • 人类门禁 HITL：金融交易、数据删除、生产变更、部署等不可逆操作应强制人类审批。

① 数字主权 / 本地合规

非英语世界独有的硬选型维度。德国 Bitkom：68% 认为过度依赖美中 AI；法国把 RGPD 合规当 AI 视频工具的选型标准。

② Godot 崛起全球同步

各语种用不同硬数据佐证：德（Steam 47→1500+ 款）、葡/俄（磁盘 164MB vs 20GB、编译快 31 倍）、日（上位替代论）。

③ 母语文档量是头号变量

韩：韩文文档量第一标准；葡：巴西葡语合成语音；日：VOICEVOX 日语视频栈。本地化常压过纯技术优劣。

④ SDD 分工趋同、口号各异

日"AI 写、人决定"、西"仅 0–20% 可委托 AI"、俄"开发者变设计工程师"、韩"规格能力"。同一结论：选型与写规格是人类的活。

⑤ 工具分工被独立发现

日、韩两个互不相通的社区都得出「Claude Code + Cursor 按阶段/前后端分工」——说明这条实践很稳健。

⑥ 招聘市场决定选型

韩语最直白：用 Java/Spring 的几乎都是大公司、初创用 Node/Next——选型本质是"想进哪类公司"。

  • "Godot 上位替代论"高 — 初学者与 2D 项目首推 Godot 而非 Unity，与英文圈"Unity 默认起步"不同。
  • "ツクール vs Phaser"中 — 同人游戏特有的选型轴：无代码全套现成 vs 轻量但要自己补。
  • 日本国产 SDD 工具 cc-sdd高 — 一条命令把 Claude Code/Cursor 等"Kiro 化"、原生日语支持。
  • 对 SDD 的认知论再诠释高 — "本质是逼工程师自己把需求言语化，提升规格分辨率是人类的工作"。
  • Findy 调查中 — 自由职业工程师生成 AI 活用率 84.2%，54% 付费；Claude Code 已逼近 Copilot。
  • "别把 Next.js 当初始栈"逆流共识高 — 推荐 Vite+React+TS+react-router，与"创业默认 Next.js"对照鲜明。
  • "先让 Opus 写 PRD/TRD"中 — "学会 PRD、TRD 这两个词，完成度提升几倍"；并提出 RDD（Readme 驱动开发）。
  • 大厂 AI 分岗落地中 — Naver 做代码评审、Toss 做图像、Kakao 做垃圾分类；但"架构与支付稳定性判断仍是工程师职责"。
  • 韩文文档量是引擎选型第一标准中 — Unity、Phaser 都因此被选。
  • 数据点中 — 某调查 72% 开发者不用 vibe coding；Go 开发者 53% 指最大问题是 AI 生成"无法运行的代码"。
  • codecentric"AI 辅助开发五个等级"中 — 等级间不是优劣排序；提出"AI Readiness"作为采用前提。
  • Fraunhofer IESE 引 DORA中 — 30% 几乎不信任 AI 代码、61% 完全回避自主 Agent；"AI 是放大器，但前提是组织已做好准备"。
  • NIST 已将 Rust 列入"安全编程语言"高 — Android 内存安全漏洞 2019→2022 从 76% 降到 35%。
  • ADR 史料精确化高 — Nygard 2007《Release It!》提出、2011 博文广传；价值在 onboarding 与多年后回溯时显现。
  • 【法】数字主权 + RGPD 作为选型标准中 — 并用 Y-Statement 显式记录"接受的折中"教学架构权衡。
  • 【西】成体系的 SDD 人机分工话语高 — 人定栈/约束、AI 生成技术计划、架构师验证；Plan 阶段最常被跳过但最能防技术债。
  • 【法】一手证言中 — 法国工作室转 Godot 后"并不后悔，回 Unity 纯粹是讨厌"，看重"做的东西都归我们所有"。
  • 【法】JetBrains 2025高 — 69% 开发者已用过 ChatGPT，近半数定期用于写代码。
  • 成本/负载驱动重写中 — Java 单体迁 Rust/Go/C++，触发点是 100k+ RPS、云成本"相当于几个中级开发者工资"。
  • "全球排名 ≠ 本地市场"中 — Go 在 TIOBE 跌出前十但俄罗斯大厂持续升温；Avito 官方发文劝业界别据排名调栈。
  • X5 Tech 的六阶段 SDD中 — 多了独立的 Clarify 阶段；开发者角色重定义为"设计工程师"。
  • 金融科技分层选型中 — 近端 Scala+Akka、深层 Kotlin+Spring；点名 Scala"可读性差、编译慢对大项目致命"。
